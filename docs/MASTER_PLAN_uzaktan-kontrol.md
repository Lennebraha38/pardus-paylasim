# MASTER PLAN — Ekran Paylaşımı İyileştirme + AnyDesk-tarzı Uzaktan Kontrol + Çapraz-Platform

> **Durum:** ONAYLANDI · Uygulama başlamadı.
> **Amaç:** Bu belge tek doğruluk kaynağı. Her tamamlanan adım aşağıdaki **İlerleme Takibi** bölümünde işaretlenir ki başka bir agent yarıda kalan yerden devam edebilsin.
> **Devralma kuralı:** Yeni agent önce "İlerleme Takibi" tablosunu okur → ilk `[ ]` (pending) adımı bulur → o adımdan başlar. Her adım bitince kutuyu `[x]` yapar, **Tamamlanma Notu** satırına commit hash + kısa özet yazar.

---

## Context (Neden bu iş?)

Kullanıcı sordu: "Ekran paylaşımı iyileştirilmiş mi ve AnyDesk gibi uzaktan **kontrol** modülü eklenmiş mi?"

**Bulgu (kod incelemesi — dosya:satır doğrulandı):**
- Ekran paylaşımı **yalnızca view-only MJPEG** (port 52345, GStreamer PipeWire/X11 → screenshot fallback, TLS + PIN pinning). Sağlam ama tek yönlü seyir.
- **Uzaktan kontrol / girdi enjeksiyonu HİÇ YOK.** `stream_server.py` ve `stream_client.py`'de sıfır mouse/klavye işleme. AnyDesk-tarzı modül yok.
- Ekran tarafında somut eksikler: çözünürlük/kalite/fps hardcoded, PIN URL query'de sızıyor, CORS `*`.
- GUI tümüyle GTK4/Libadwaita/PyGObject → Windows'ta native çalışmaz. Çapraz-platform katmanı yok.

**Amaçlanan sonuç:** (1) ekran paylaşımını yapılandırılabilir + güvenli yap, (2) mevcut TLS-pinlenmiş bağlantı üstüne AnyDesk-tarzı uzaktan kontrol ekle, (3) 8 modülün eksiklerini gider, (4) Windows↔Pardus çapraz-platform yolu aç.

**Kullanıcı kararları (onaylandı):**
1. Çapraz-platform: **web istemci + Python companion agent, ikisi birden**
2. Linux enjeksiyon: **otomatik algıla** (X11→python-xlib/XTEST, Wayland→ydotool/uinput)
3. Kontrol güvenliği: **katı** (oturum onayı + kalıcı banner + kill-switch + audit)
4. MVP: **Pardus→Pardus önce**
